# Спецификация экрана «Создание товара» для Flutter (паритет с Libiss POS Web)

Документ описывает **как веб-приложение** `pos.libiss.com` (`add-product.html` + `src/js/pages/add-product.js`) **создаёт товар**, включая **UX, визуальную систему, тексты и API**. Цель — реализовать в Flutter **то же поведение и максимально близкий вид**.

Исходники для сверки:

- Разметка: `add-product.html`
- Логика: `src/js/pages/add-product.js`
- Стили: `src/styles.css`, `src/css/base.css`
- Строки RU/EN: `src/js/lib/translations.js` (ключи `addProduct.*`)
- Селектор категорий/сезона/типа размера: `src/js/components/category-selector.js`
- HTTP: `src/js/lib/api.js` (`getApiBase()`, `uploadImage`, `request` с `Authorization: Bearer`)

Краткий обзор эндпоинтов уже есть в `docs/ADD_PRODUCT_FLOW.md`; здесь — расширение под **дизайн и Flutter**.

---

## 1. Вход, навигация, редактирование

| Сценарий | Поведение |
|----------|-----------|
| Нет токена | Редирект на логин: `login?redirect=<текущий путь>` (в вебе `localStorage.userToken`) |
| Создание | Пустая форма, справочники грузятся при старте |
| Редактирование | В URL параметр `id=<uuid товара>` → `GET /products/:id` с токеном, заполнение полей, чекбоксов, вариаций, `uploadedPhotos` из `imageUrlsByColor` |
| После успеха | Очистить черновик, показать краткий «успех», через **~1.5 с** перейти в кабинет на вкладку товаров (в вебе `office.html#products` → в Flutter свой роут списка товаров) |

Заголовок экрана (AppBar): ключ **`addProduct.title`** — RU: «Создание товара», EN: «Create product». Кнопка «назад» ведёт в кабинет (как `data-app-logo-href="/office.html"` в шапке веба).

## 2. Визуальная система (дизайн-токены)

Скопируйте из `src/css/base.css` и `src/styles.css`.

### 2.1 Цвета (`:root`)

| Токен | Значение | Назначение |
|-------|----------|------------|
| `--bg` | `#ffffff` | Фон страницы |
| `--text` | `#0b0f0f` | Основной текст |
| `--muted` | `#66707a` | Подписи полей (label), второстепенный текст |
| `--card` | `#f6f8f8` | Карточка формы, фон чипов |
| `--border` | `#e5ecec` | Обводки |
| `--accent` | `#25c79a` | Акцент, градиент кнопки |
| `--accent-strong` | `#12a57c` | Усиленный акцент, theme-color в meta |
| Тень карточки | `0 20px 60px rgba(11, 15, 15, 0.08)` | `box-shadow` формы |
| Ошибка | `#d64545` | Текст статуса ошибки, невалидный input |
| Фокус input | `border` + `box-shadow: 0 0 0 3px rgba(37, 199, 154, 0.12)` | Как на вебе |

Фон страницы `.page`: **два радиальных градиента** с зелёным тинтом (см. `--grad` в `base.css`) — для паритета можно использовать `Container` с `LinearGradient`/`RadialGradient`, имитируя тот же эффект.

### 2.2 Типографика

- Шрифт: **Inter**, fallback `Segoe UI`, `system-ui`, `-apple-system`, `sans-serif`
- **Eyebrow** над формой: `13px`, `letter-spacing: 0.16em`, `uppercase`, цвет `muted` — текст ключа **`addProduct.eyebrow`** (в RU сейчас «Товар»; подзаголовок **`addProduct.subtitle`**)
- Подписи полей `.field label`: `13px`, `uppercase`, `letter-spacing: 0.08em`, цвет `muted`
- Основной текст в инпутах: `15px`
- На узких экранах (≤768px) в вебе для input **минимум 16px** — во Flutter избегайте «зума» iOS: задайте размер текста полей ≥16

### 2.3 Скругления и отступы

| Элемент | Значение |
|---------|----------|
| Карточка формы `.form-card` | `border-radius: 24px` (`--radius-lg`), padding **28px**, border `1px solid border` |
| Поля ввода | `border-radius: 14px`, padding **12px 14px** |
| Кнопки `.btn` | **pill**: `border-radius: 999px`, padding **14px 20px**, `font-weight: 600`, `15px` |
| Первичная кнопка | Градиент `135deg` от `--accent` к `--accent-strong`, белый текст, тень `0 12px 30px rgba(37, 199, 154, 0.35)` |
| Вторичная кнопка | Обводка `border`, фон полупрозрачный от `--bg` |
| Контентная колонка | `max-width: 720px` по центру; верхний отступ под шапку **~96px + safe area** (`form-page` / `add-product-page`) |
| Нижний отступ | **~80px + safe area** под фиксированную панель действий при необходимости |

### 2.4 Safe area

Учитывать `padding` от `MediaQuery.of(context).padding` (и `viewPadding` для клавиатуры), как в вебе `env(safe-area-inset-*)`.

## 3. Мастер: 5 шагов (индексы 0–4)

Один видимый шаг; кнопки снизу: **«Назад»** (secondary) | **«Далее»** / на последнем шаге **«Создать товар»** (primary). На шаге 0 кнопка «Назад» **disabled** (в вебе `prevBtn.disabled`).

### Шаг 0 — Основная информация

Порядок полей сверху вниз (как в HTML):

1. **Название** — `name`, обязательное, placeholder **`addProduct.namePlaceholder`**
2. **QR-код** — `qrCodeUrl`, **только чтение** для пользователя; заполняется **только сканером** + иконка-кнопка камеры справа (`barcode-wrapper`: flex row, gap 8px)
3. **Описание** — `description`, textarea ~3 строки, необязательно, hint **`addProduct.descriptionHint`**
4. **Пол** — radio group, обязательно, значения: `unisex` (default), `male`, `female` — подписи **`addProduct.genderUnisex`**, **`genderMale`**, **`genderFemale`**
5. **Категория** — обязательно; в вебе выпадающий иерархический селектор (`CategorySelector`): кнопка-триггер с chevron, выбор листа дерева; значение в скрытом поле UUID
6. **Сезон** — необязательно; тот же паттерн селектора; значение — id сезона (число)
7. Сетка **две колонки** (`grid two`): **Цена** (number, min 0, step 0.01, required) | **Скидка %** (0–100, step 1)

**Блок «итоговая цена»** рядом со скидкой: если `price > 0` и `discount > 0`, показать зачёркнутую старую цену и новую с **`TJS`** (как в вебе `updateFinalPrice`). Классы: `.final-price`, `.old-price`, `.new-price` (новая — `accent-strong`, жирная).

Валидация: нативная по required + для категории отдельное сообщение: **`addProduct.errorCategoryRequired`** или fallback «Выберите категорию» (в переводах ключ может отсутствовать — добавьте в приложении).

### Шаг 1 — Цвет и размеры

- **Цвета**: горизонтальные переносы, чекбоксы. Каждый элемент — контейнер **56×56**, `border-radius: 14px`, внутри квадратный свотч **32×32**, `border-radius: 8px`, цвет из API `hex`. Скрытый checkbox; выбранное состояние: обводка `accent`, лёгкий фон `accent` ~8%, свотч **scale 1.2**. Hover: `translateY(-2px)`.
- **Тип размера**: сверху селектор как у категории; при выборе → `GET /sizes/?size_type_id=<id>`. Если типов нет → `GET /sizes/`.
- **Размеры**: чипы в ряд, **min-width 48**, **height 40**, `border-radius: 10px`, gap 8px. Выбранный чип: фон и бордер `accent`, текст белый, тень `0 4px 12px rgba(37, 199, 154, 0.25)`.

**Правило:** минимум **1 цвет и 1 размер**. Иначе показать ошибку — в вебе для обоих случаев используется **`addProduct.errorColorRequired`** («Выберите хотя бы один цвет») — *для паритета можно повторить баг* или разделить на два сообщения (рекомендуется для UX: отдельно «выберите размер»).

### Шаг 2 — Вариации

Декартово произведение **каждый выбранный цвет × каждый выбранный размер** → одна строка вариации.

При первом входе на шаг (не режим редактирования с уже загруженными данными): вызвать пересборку списка:

- `stock` по умолчанию **"1"**
- `price` по умолчанию = базовая цена с учётом скидки (как на шаге 0)
- `qrCodeUrl` = значение с шага 0 или сохранённое
- `discount`, `originalPrice` наследуются от базовых

**Группировка UI:** по цвету. Для каждого цвета — блок `.variations-group-by-color` (padding 16px, border, radius 8px), заголовок: свотч 20×20 + имя цвета.

Внутри группы — строки `.variation-row` (фон `bg-secondary` / в теме это второй фон, border, padding 16px, radius sm):

- Слева подпись размера (жирный)
- Справа сетка полей **3 колонки** на широком экране: **Кол-во** (`addProduct.variationStock`), **Цена** (`variationPrice`), **QR** (в вебе подпись захардкожена «QR-код», placeholder «Только со сканера») + кнопка сканера
- На экране **&lt; 600px** — колонки **в столбик** (одна колонка)

Глобальные функции сканера в вебе: открыть полноэкранный оверлей `.scanner-modal` (затемнение 80%), белая карточка 90% ширины max 400px, превью камеры, кнопка «Закрыть» — **`addProduct.stopScan`**. Распознавание QR → запись в активное поле → закрыть.

### Шаг 3 — Фото по цветам

- Заголовок **`addProduct.photos`**, подсказка **`addProduct.photosHint`**
- Для **каждого выбранного цвета** — блок `.photo-group`:
  - Заголовок h4: свотч + имя цвета
  - Сетка превью `.photos-for-color__preview`: миниатюры с кнопкой удаления «×» в углу (`.photo-remove-btn`)
  - Действия: две вторичные кнопки-лейбла:
    - **`addProduct.addPhotos`** — выбор из галереи, `accept image/*`, `multiple`
    - **`addProduct.takePhoto`** — `capture` задней камеры (`environment` в вебе)

**Лимит:** максимум **5** изображений на **один цвет** (сумма уже загруженных URL + новых файлов). Превышение — alert «Максимум 5 фото на один цвет» (вынести в строки локализации).

Файлы до сабмита хранятся в памяти; при редактировании существующие URL — отдельно, с возможностью удаления.

### Шаг 4 — Проверка

1. Заголовок **`addProduct.review`**
2. Блок **режим загрузки** (радио):
   - **`addProduct.uploadPhotoMode`**
   - Вариант 1 (default): `value=compressed` — **`addProduct.uploadModeCompressed`**
   - Вариант 2: `value=original` — **`addProduct.uploadModeOriginal`**
3. При открытии шага в вебе сначала показывается **лоадер** в области обзора: спиннер + текст «Конвертация фото, пожалуйста подождите...» — выполняется **предпросмотрное** сжатие через canvas для всех новых файлов (качество **0.8**, max ширина по умолчанию из функции — см. ниже); результат в `compressedPhotos` для превью. При ошибке сжатия подставляется оригинал.
4. Сводка:
   - Секция `.review-section`: строки **Название, Категория, Сезон, Базовая цена, Скидка** — ключи `addProduct.reviewName` … `reviewDiscount`
   - Далее по группам цвета: превью фото (мини `.review-thumb`) или текст «Нет фото», таблица размеров: бейдж размера, «X шт.», цена с суффиксом **TJS**

Кнопка основного действия на этом шаге: **`addProduct.submit`** / при отправке **`addProduct.submitting`**.

## 4. Оверлей загрузки при сабмите

Полноэкранный `.loading-overlay`: фон белый 90% непрозрачности, по центру спиннер (круг, анимация rotate), заголовок и подзаголовок.

Последовательность текстов:

1. «Подготовка данных...»
2. Для каждого фото: «Загрузка фото (n/total)» + подзаголовок «Осталось примерно X сек...» если total &gt; 1
3. «Создание товара...», «Пожалуйста, подождите»
4. При редактировании: «Обновление товара...»
5. Успех: «Готово!» + подзаголовок про переход

## 5. Черновик (localStorage в вебе)

Ключ **`addProductDraft`**. Сохранять при «Далее» и при изменениях фото/вариаций. Содержимое: номер шага, поля формы, выбранные id цветов/размеров, `sizeTypeId`, массив `variations`.

При открытии страницы черновик подмешивается в поля; **номер шага в вебе не восстанавливается** (закомментировано) — для Flutter можно сделать лучше: восстанавливать шаг опционально.

После успешного создания/обновления черновик **удаляется**.

## 6. API (база из `VITE_API_URL`, путь `/api/v1`)

Префикс как в `api.js`: все запросы к `{base}/...`.

### 6.1 Справочники (без токена в вебе)

| Метод | Путь |
|-------|------|
| GET | `/categories/` |
| GET | `/seasons/` |
| GET | `/colors/` |
| GET | `/size-types/` |
| GET | `/sizes/?size_type_id=<id>` или `/sizes/` |

### 6.2 Редактирование

GET `/products/:id` с **Bearer**.

### 6.3 Загрузка изображений (перед POST товара)

Для **каждого нового файла** по каждому цвету:

- POST **`/upload/image?folder=products&useCloudinary=false`**
- Если после обработки на клиенте тип файла `image/webp`: добавить **`&readyWebp=true`**
- Тело: `multipart/form-data`, поле файла строго **`image`**
- Заголовок: `Authorization: Bearer <token>`

**Режим `compressed` (default):** если файл не WebP, перед загрузкой перекодировать в WebP: **качество 0.82**, max ширина **3024** px (пропорционально высота). Если уже WebP — не перекодировать, всё равно `readyWebp=true`.

**Режим `original`:** отправлять файл как есть; `readyWebp=true` только если исходный тип WebP.

Ответ: взять URL из `url` или `data.url` или `data` (как в `uploadImage`).

### 6.4 Создание / обновление товара

- Создание: POST **`/shop/products/`**
- Обновление: PUT **`/shop/products/:id`**

Тело JSON (корень):

| Поле | Тип | Примечание |
|------|-----|------------|
| `name` | string | trim |
| `description` | string | trim |
| `gender` | string | `male` \| `female` \| `unisex` |
| `categoryId` | string (uuid) | |
| `seasonId` | int \| null | пусто → null |
| `brand` | string | из формы или **`"Libiss"`** |
| `sortOrder` | int | в вебе всегда **0** |
| `qrCodeUrl` | string \| null | |
| `variations` | array | см. ниже |

Элемент **`variations[]`** (одна запись на пару цвет×размер):

| Поле | Тип |
|------|-----|
| `sizeIds` | int[] |
| `colorIds` | int[] |
| `price` | number — если &gt; 0 использовать; иначе `originalPrice - originalPrice * discount/100` |
| `originalPrice` | number \| null |
| `discount` | number |
| `stockQuantity` | int |
| `qrCodeUrl` | string, **опустить** если пусто |
| `imageUrls` | string[]?, опционально из существующей вариации |
| `imageUrlsByColor` | `Map colorId → string[]` — для текущей вариации: если есть загруженные URL для `v.colorId`, отправить `{ "<colorId>": [ urls ] }` |

Важно: в вебе для **каждой** строки вариации в массиве дублируется свой `imageUrlsByColor` только с ключом своего цвета (см. `add-product.js` map).

### 6.5 Ошибки

Если ответ с `error: true` — показать `message`. Ключ **`addProduct.errorPhotoUpload`** при ошибке загрузки фото. Для сохранения товара fallback **`addProduct.errorCreate`** (убедитесь, что строка есть в локализации Flutter).

## 7. Сжатие изображения (алгоритм как на вебе)

Для превью на шаге 4 вызывается `compressImage(file)` — **quality 0.8**, **maxWidth 3024** (дефолты функции).

Для реальной загрузки в режиме compressed: **`compressImage(file, 0.82, 3024)`**.

Логика: прочитать bitmap → если ширина &gt; maxWidth, масштабировать → экспорт в **WebP** с заданным quality → новый файл с расширением `.webp`.

В Flutter: `flutter_image_compress` или `image` + `encodeJpg` не даст WebP-паритет; для полного совпадения используйте пакет с кодированием **WebP** или нативный канал.
