# Execution Checklist: Multi-Store внедрение

Краткий рабочий чеклист для команды.  
Подробная архитектура и контекст: `docs/MULTI_STORE_ROADMAP.md`.

---

## Sprint 0 - Подготовка и безопасность

- [ ] Утвердить целевую модель: `1 owner -> N stores`.
- [ ] Зафиксировать API versioning (`v1` legacy, `v2` multi-store).
- [ ] Добавить feature flags:
  - [ ] `ff_multi_store_enabled`
  - [ ] `ff_store_transfer_enabled`
  - [ ] `ff_store_visibility_cross_stock`
  - [ ] `ff_dual_write_inventory`
- [ ] Подготовить rollback-инструкцию (флаги off).
- [ ] Согласовать тестовые данные для пилотного владельца.

---

## Sprint 1 - Global API (owner/stores/license slots)

- [ ] Добавить/обновить модель владельца и магазинов.
- [ ] Реализовать лимит магазинов по тарифу (`maxStores`).
- [ ] Реализовать API:
  - [ ] создание магазина владельцем
  - [ ] список магазинов владельца
  - [ ] активация/деактивация магазина
  - [ ] получение лимитов плана
- [ ] Добавить проверки:
  - [ ] нельзя создать магазин сверх лимита
  - [ ] магазин всегда привязан к owner
- [ ] Добавить unit/integration тесты на лимиты и доступы.

Definition of Done:

- [ ] Владелец может создать до `maxStores` магазинов.
- [ ] Старые клиенты не затронуты.

---

## Sprint 2 - Local API DB migration (inventory v2)

- [ ] Создать таблицы:
  - [ ] `inventory_locations`
  - [ ] `inventory_balances`
  - [ ] `inventory_transfers`
  - [ ] `inventory_transfer_items`
  - [ ] `inventory_transfer_events`
- [ ] Создать legacy location для существующих данных.
- [ ] Мигрировать текущие остатки в `inventory_balances`.
- [ ] Включить `dual-write` (временно).
- [ ] Добавить сверку `legacy stock` vs `v2 balances`.

Definition of Done:

- [ ] Миграция проходит без даунтайма.
- [ ] Старые эндпоинты продолжают работать.

---

## Sprint 3 - Local API v2 (transfer flow)

- [ ] Реализовать endpoint "наличие по магазинам владельца".
- [ ] Реализовать endpoint "создать запрос перемещения".
- [ ] Реализовать endpoint "подтвердить/отклонить перемещение".
- [ ] Реализовать endpoint "принять перемещение".
- [ ] Реализовать журнал перемещений (audit trail).
- [ ] Проверки прав:
  - [ ] источник и получатель одного owner
  - [ ] достаточно остатка в источнике
  - [ ] корректные статусы переходов

Definition of Done:

- [ ] End-to-end перемещение проходит в API.
- [ ] Неверные операции блокируются понятными ошибками.

---

## Sprint 4 - POS App (read-only cross-store)

- [ ] Показать остаток текущей точки.
- [ ] Показать блок "есть в других магазинах".
- [ ] Отобразить доступные размеры/вариации по другим точкам.
- [ ] Добавить кнопку "Запросить перемещение" (если флаг включен).
- [ ] Сохранить fallback на legacy-режим.

Definition of Done:

- [ ] Кассир видит наличие в других магазинах.
- [ ] При выключенных флагах касса работает как раньше.

---

## Sprint 5 - POS App (операционный режим)

- [ ] Экран входящих/исходящих перемещений.
- [ ] Действия подтверждения/приемки.
- [ ] Жесткое списание продаж с текущей точки.
- [ ] Уведомления о статусах перемещений.

Definition of Done:

- [ ] Сценарий "нет размера на A -> запрос в B -> приемка -> продажа на A" работает полностью.

---

## Sprint 6 - `pos.libiss.com_site` (owner onboarding)

- [ ] Страница регистрации/входа владельца.
- [ ] Страница "Мои магазины".
- [ ] Форма "Создать магазин".
- [ ] Страница тарифа и лимита магазинов.
- [ ] Статусы магазина: `pending_setup`, `active`, `inactive`.
- [ ] Экран инструкций подключения POS по магазину (`store_uuid`).

Definition of Done:

- [ ] Владелец может с сайта открыть и активировать магазины в рамках лимита.

---

## Sprint 7 - Совместимость, мониторинг, rollout

- [ ] Провести контрактные тесты `v1`.
- [ ] Провести интеграционные тесты `v2`.
- [ ] Включить пилот на 1 владельце.
- [ ] Проверить метрики:
  - [ ] ошибки API
  - [ ] рассинхрон остатков
  - [ ] время обработки перемещений
- [ ] Постепенно расширять rollout.
- [ ] Подготовить отключение `dual-write` после стабилизации.

Definition of Done:

- [ ] Пилот стабилен.
- [ ] Rollout без инцидентов.
- [ ] Старые клиенты не сломаны.

---

## Критические проверки перед production

- [ ] Legacy путь продаж работает при `ff_multi_store_enabled = false`.
- [ ] Любой флаг можно выключить без миграции назад.
- [ ] Миграция БД повторяемая и безопасная.
- [ ] Есть скрипт сверки остатков и инструктаж поддержки.
- [ ] Есть runbook на инциденты (rollback + диагностика).
